# Security

Report vulnerabilities privately to **incord@jesklabs.com**. Do not open a public issue containing exploit details, credentials or private account data.

Include the affected version or commit, a concise description, reproducible steps, impact and a minimal proof of concept when possible. Redact tokens, email codes, library contents and personal information. Use test accounts you control; do not access other people's data or disrupt the hosted service.

The latest default-branch version is the supported development version. Reports will be reviewed as maintainer availability permits; there is no guaranteed response SLA or paid bounty. Coordinate public disclosure after a fix can be assessed and released.

For ordinary bugs and ideas, use GitHub issues. Never commit `.dev.vars` or production credentials.
